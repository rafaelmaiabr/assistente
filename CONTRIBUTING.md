# Contribuir

1. Criar uma issue com problema, escopo, critérios de aceite e validação antes de implementar.
2. Criar branch `feat/<issue>-<descricao>` ou `fix/<issue>-<descricao>` a partir da base atual.
3. Entregar uma parte utilizável por PR; referenciar `Closes #numero` somente quando todo o aceite estiver cumprido.
4. Documentar como executar, o que foi testado e limitações. Não apresentar funcionalidades planejadas como prontas.
5. Fazer push e abrir PR. Manter a issue aberta enquanto houver critérios pendentes.

Não versionar segredos, modelos, logs de voz, históricos de conversa ou configuração local. Novos recursos devem funcionar sem serviços pagos por padrão. O microfone precisa de controle explícito e estado visível.
